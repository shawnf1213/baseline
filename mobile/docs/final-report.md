### Backend (`backend/`, deployed)

- `GET /api/sports` — sport visibility from `APP_SPORTS`.
- `GET /api/board/live?book=prizepicks|underdog` — the live tennis market parsed server-side (`src/live_board.py`, mirrors the bot's parsers; the phone never downloads Underdog's 16 MB payload), merged with prices from the pricer.
- `src/board_pricer.py` — **prices the live tennis board on the backend**: every 10 minutes, one row at a time (2 s gap), soonest match first, through the same `prop_calculate` function `/api/prop/calculate` uses (same cache, same model), persisted to the durable cache every 5 rows so a redeploy keeps what was priced. Rows re-price after 2 h or when the line moves. Status is in the live-board response (`pricer`).
- `src/gate.py` — the member gate (§3), with `POST/GET /api/admin/enforce` (admin token) to flip it instantly.
- `src/push.py` + `push_tokens` table + `POST /api/push/{register,unregister,prefs,send}` — push registration and fan-out (§4).
- `core/service_token.py` + `is_service_request()` — service callers.
- Account deletion now also deletes the identity's push tokens.

### Bot (`discord-bot/`, deployed)

- `service_token.py` — every backend call carries `X-Service-Token` (the two `to_thread` call sites the shared helpers did not cover — subscription-role sync, closing-line observe — were patched after they surfaced as 401s; see §6).

## 2. Decisions made on my own

1. **Whop = role-based members.** The backend has no Whop flag; Whop grants the Discord premium role, so the account sheet shows *Manage on Whop* (`https://whop.com/hub`) when `source == "discord"` and the Stripe portal only when `source == "stripe"`. Owner/reviewer see neither.
2. **Backend pricing cadence.** Pass every 10 min, 2 s between rows, re-price after 2 h, failed rows retried after 1 h (transient after 10 min), 400 rows per pass max. A cold pass is slow by design (30–60 s per unseen player); the board fills over the first hour and is near-instant after.
3. **NFL shadow picks are shown** on the Picks tab, as the website shows them — all 482 NFL record rows are `shadow=1` and the boards are posted to subscribers regardless.
4. **Age rating** declared under "Gambling and Contests" (17+/18+) rather than pretending the lines are not sportsbook lines.
5. **Enforcement default** is OFF in the environment (`PREMIUM_ENFORCE` unset) and ON through the durable override, so a redeploy cannot silently drop the gate and a bad day can be fixed with one command.
6. **Restricted endpoints** keep their own guards *inside* the gate: the gate admits a service or admin token, then the handler checks what it always checked (e.g. `/api/billing/subscribers` still wants its sync token). That is why `gate_check.py` shows 403/401 for two restricted routes with only the service token — expected.
7. **Reviewer session for screenshots** was minted on the backend (`railway run`, never printed) for the reviewer account, which is premium-only, and used on a local web build at `localhost:5173`. The web build itself got a localStorage session fallback (`auth.ts`, web only).
8. **Push sends only after a successful Discord send**, one per board/recap post. The Underdog tennis board is a second tennis push (titled as Underdog). Push preferences default to all on.
9. **Tapped notification → Picks tab of that sport.** Nothing deeper, to keep the first release simple.
10. **Research prop history uses the board line when there is one**, else the player's average, and says which.
11. **Removed from the plan:** nothing. Deferred: NBA/NFL projections' deeper driver breakdowns beyond what the Discord card shows.
